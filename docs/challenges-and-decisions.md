# 어려웠던 점과 결정 기록

## 1. LLM 스크립트 품질

문제:
- 초기 스크립트가 정보 전달은 되지만 클릭 유도력과 몰입감이 약했다.
- ETF 소재는 단순 순위 나열만 하면 영상이 평평해진다.

결정:
- “추천 종목”보다 “돈의 방향”, “따라 사기 전 기준”, “시장 온도계” 같은 프레임을 사용한다.
- 장면마다 하나의 메시지만 남기고 문장을 짧게 압축한다.
- 투자 권유로 보이지 않도록 리스크와 비중 관점을 반드시 넣는다.

## 2. 참고 영상 스타일 반영

문제:
- 사용자가 원하는 레이아웃은 일반 카드형 템플릿보다 훨씬 강한 쇼츠형 화면이었다.
- 상단 훅, 중앙 이미지, 하단 자막 박스의 균형을 맞춰야 했다.

결정:
- 검정 상단 훅 문구와 노란 강조어를 고정 패턴으로 둔다.
- 하단 자막은 흰색 박스에 넣어 모바일에서 안정적으로 읽히게 한다.
- 장면 이미지는 중앙에 크게 배치하고, 자막과 겹치지 않게 프레임 검수를 한다.

## 3. Remotion 렌더 멈춤

문제:
- 일부 참고 스타일 렌더에서 Remotion이 마지막 단계에서 멈췄다.

결정:
- 단기적으로는 Pillow로 프레임을 직접 만들고 FFmpeg로 인코딩하는 우회 경로를 사용했다.
- 장기적으로는 참고 쇼츠형 레이아웃도 Remotion 컴포넌트로 안정화하는 것이 좋다.

## 4. 이미지 생성 API 사용량 확인

문제:
- OpenAI 이미지 생성 API를 사용했는데 Platform Usage에 바로 보이지 않았다.

가능성:
- OpenClaw가 사용하는 키/OAuth가 사용자가 보고 있는 Default project와 다를 수 있다.
- Usage 반영이 지연될 수 있다.
- provider 설정이 다른 프로젝트에 연결되어 있을 수 있다.

확인 결과:
- 이미지 생성 provider는 OpenAI로 설정되어 있었고, 기본 모델은 `openai/gpt-image-2` 계열이었다.

## 5. 썸네일 한글 텍스트

문제:
- 이미지 생성 모델에 한글 텍스트까지 맡기면 오탈자와 깨짐 위험이 크다.

결정:
- 이미지 생성은 텍스트 없는 배경까지만 사용한다.
- 한글 카피는 Pillow로 직접 합성한다.
- 사용자의 피드백에 따라 텍스트 굵기와 문구를 빠르게 재합성한다.

## 6. GitHub 업로드 범위

문제:
- 작업 폴더에는 비밀키, OAuth 토큰, 가상환경, 대용량 영상, 개인 메모리 파일이 섞여 있다.

결정:
- GitHub에는 재사용 가능한 코드, 설정 예시, 스크립트/장면 JSON, 업로드 메타데이터, 문서만 올린다.
- env 파일, secrets 폴더, client_secret.json, 가상환경, 대용량 렌더, OpenClaw 개인 메모리는 제외한다.

## 7. Taehyung 목소리 고정 실패

문제:
- 코드 기본값은 Taehyung으로 되어 있어도 env의 ELEVENLABS_VOICE_ID가 다른 목소리로 덮어썼다.
- 사용자는 Taehyung - Natural, Friendly and Clear를 고정 목소리로 원했다.

결정:
- 쇼츠 기본 TTS는 m3gJBS8OofDJfycyA2Ip로 강제한다.
- 일회성 예외가 필요할 때만 MEDIA_AGENT_ALLOW_CUSTOM_ELEVENLABS_VOICE=1을 사용한다.
- ElevenLabs 실패 시 조용히 fallback하지 않고, 최종 전달 전에 실패를 드러낸다.

## 8. 팬더 캐릭터 일관성

문제:
- 이미지 생성 모델은 장면마다 팬더 얼굴, 안경, 나이대 인상을 다르게 만들 수 있다.
- 복장/제스처까지 과하게 고정하면 장면 다양성이 떨어진다.

결정:
- 팬더 얼굴 고정 조건을 visual planner와 image prompt exporter에 반복 주입한다.
- 얼굴 비율과 안경/눈무늬만 고정한다.
- 복장, 제스처, 자세, 소품, 배경은 장면별로 자유롭게 바꾼다.

## 9. 하단 프로그레스바

문제:
- 참고 레이아웃에서는 하단 프로그레스바가 필요하지 않고, 자막/하단 훅과 경쟁했다.

결정:
- Remotion 템플릿과 Pillow reference layout 렌더러에서 프로그레스바를 제거한다.
- 최종 검수 시 하단 프로그레스바가 없는지 프레임으로 확인한다.
